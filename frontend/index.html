SAGA Distributed Pattern & Compensation

When checkout runs, order-service calls multiple services in a distributed saga. If payment fails, automatic compensation restores the product inventory!

1
Verify Customer
USER-SERVICE (:8081)
2
Reserve Inventory
PRODUCT-SERVICE (:8082)
3
Process Payment
PAYMENT-SERVICE (:8084)
4
Commit / Rollback
ORDER-SERVICE (:8083)

How SAGA Works Here:

  1. 1. Feign Call to User Service: Validates that the Customer ID exists in the database.
  2. 2. Feign Call to Product Service: Decrements stock quantity by the requested amount.
  3. 3. Feign Call to Payment Service: Charges the user's card/UPI.
  4. 4. Compensation Logic: If Payment Service rejects the transaction (or fails), order-service catches the exception and immediately invokes PUT /api/products/{id}/restore-stock to return reserved stock back to the shelf!
